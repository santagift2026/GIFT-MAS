Safe launch checklist
1. Connect a wallet through its official provider (never ask for a seed phrase).
2. Confirm the selected network is Solana mainnet or clearly labeled devnet during testing.
3. Validate the recipient and asset; verify the GFTM mint address from an official project source before enabling token transfers.
4. Build and simulate the transaction, show recipient, exact amount, token mint (for GFTM), and estimated network fee.
5. Require the sender to review and sign in their own wallet, then confirm the transaction signature on Solana Explorer.
6. Handle rejection, insufficient balance, stale quotes, and failed confirmations without claiming success.

🧪 Devnet SOL gifting test process

Use this staged checklist before enabling any real transfer. Devnet SOL is for testing and has no intended monetary value. This guide does not itself send a transaction, and the current gift form remains preview-only.

  1. Switch your wallet to Solana Devnet. Confirm the network inside the wallet before connecting; never test with mainnet funds.
  2. Fund a test wallet. Use an official Solana devnet faucet or wallet-supported faucet. Keep only test funds in this wallet.
  3. Prepare two test addresses. Use a sender wallet and a recipient wallet you control. Copy the recipient public address and verify every character.
  4. Test the preview first. Enter a small amount, check the asset, recipient, and optional message, and confirm that the page says “preview only” and sends nothing.
  5. Implement the devnet transaction separately. The next code milestone must explicitly target the devnet RPC, validate the address and amount, fetch the fee/balance, simulate the transaction, and display the full transfer details before requesting a wallet signature.
  6. Verify the result independently. After an approved test transfer is implemented and signed, check its signature and confirmation on Solana Explorer with the Devnet cluster selected. Record success only after confirmed status; test rejection and failure cases too.

Safety gate: do not switch this flow to mainnet or enable GFTM transfers until devnet tests pass, the token mint is independently verified, and transaction details are reviewed before every signature.

Santa's FAQ

Is the token already live?

No. This is a website concept. A token address should only be added after deployment is actually completed and independently verified.

Can I send an on-chain gift here now?

A limited SOL test transfer can be submitted to Solana Devnet only through the separate test button after balance/fee checks, simulation, explicit confirmation, and wallet signing. Devnet SOL has no intended monetary value. Mainnet SOL gifting is not enabled, and the form's Review button alone only previews details. GFTM transfers require the correct deployed SPL-token mint and recipient token account, and remain disabled.

Why is Giftmas token gifting disabled?

The GFTM mint address and token deployment have not been verified. Keeping the option disabled prevents users from accidentally sending a different token that happens to use the same ticker. It should only be enabled after the mint and token details are confirmed.

Can I build the website for free?

Yes. A simple static website can be hosted on a free tier, subject to the host's current terms and limits. A custom domain, advanced services, or blockchain transactions may cost money.

Will holders receive gifts or profits?

No rewards or profits are promised. Any future gifting feature needs clear eligibility rules, funding, technical implementation, and applicable legal review.
